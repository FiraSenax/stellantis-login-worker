The Stellantis Vehicles HACS integration does the vehicle work. This small add-on replaces its shared login helper with a browser on your own Home Assistant host.

That is why this project exists: to use the main integration without sending login credentials through a shared, externally operated helper. It does not replace the integration or make the vehicle API local.

Install on HA OS

  1. Install the main Stellantis Vehicles integration through HACS if you do not already use it.
  2. Add our repository using the button above. Install Stellantis Login Worker from the app/add-on store and start it. A source build can take several minutes.
  3. Copy the helper’s internal address from its startup log. It looks like http://<addon-hostname>:3000. The actual hostname depends on your installation.
  4. Open the integration’s login form and enter that address in Login service URL before entering your credentials. If your integration supports it, save the address in Reconfigure → Global preferences first.
  5. Finish login and check that the integration loads. A healthy helper alone does not prove that authentication succeeded.

No host port is published by default. Automatic discovery depends on the installed integration version; manual URL configuration is supported.

What to expect

Does this work without the Stellantis cloud?

No. It removes the shared login intermediary. Stellantis still authenticates your account and provides vehicle data and commands.

Is this installed through HACS?

The vehicle integration is. This helper is a separate Home Assistant app/add-on because it runs Chromium in a container. This repository does not maintain a competing copy of the vehicle integration.

What happens to my password?

The integration sends it to the helper you configure. The HTTP handler passes it to the browser for that attempt and does not save it in a configuration file. The worker is unauthenticated; keep its port internal and do not publish it to the internet.

Does it solve every login problem?

No. Provider outages, changed login pages and interactive challenges can still prevent login. The helper reports failures and does not silently switch to a public login service.
